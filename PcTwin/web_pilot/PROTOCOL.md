# WebPilot ⇄ Remoter 串口线协议（v1，2026-10-16）

网页遥控台 → Remoter 核心板（F103C8T6）的输入线协议。固件侧实现：
`Hardware/Remoter/UserApp/web_input.h`（解析）+ `remoter_app.c`（看门狗/发送）。
**改这里必须同步 web_input.h 与本文件**（串口帧没有 _Static_assert 编译期护栏，
靠本文件纪律对表）。

## 1. 物理层

- USB-TTL 接 Remoter 板 USART1 调试口：**TX/RX 交叉、共地、3.3V 电平**
  （板 PA9=TX → 线 RX，板 PA10=RX → 线 TX）。
- 115200-8-N-1。同一口双向：板→网页 = `[RMT]` 文本日志行，网页→板 = 下述
  二进制帧。方向不对称互不干扰。

## 2. 下行帧（网页 → 板）

**10 字节定长二进制，小端**，20Hz 心跳（50ms 一帧）+ 输入变化即发
（最小间隔 15ms 防刷屏）：

| 字节 | 字段 | 类型 | 含义 |
|---|---|---|---|
| `[0]` | 帧头 | u8 | 恒 `0x5A`（重同步锚点） |
| `[1]` | wseq | u8 | 网页帧序号，u8 回绕（链路诊断，板不消费） |
| `[2..3]` | vx | i16 LE | **轴逻辑量 −1000…+1000**（发送端钳位；同 rc_cmd.h v2 冻结帧字段） |
| `[4..5]` | vy | i16 LE | 同上 |
| `[6..7]` | keys | u16 LE | 方向刀位图（布局见 §3） |
| `[8]` | estop | u8 | 1 = 急停闩锁态 |
| `[9]` | CRC8 | u8 | 覆盖 `[1..8]`：poly 0x07、初值 0x00、不反射、无异或输出 |

校验参考向量：`WebInput_Crc8("123456789") = 0xF4`。

**无应用层重传**：帧错了板端丢弃等下一拍（20Hz 冗余足够），CRC 只防错帧不追帧。

> **本帧不含 omega**：它是 RcInput_Raw_t（原始输入）的镜像——K_6 以 keys
> bit10/11 进帧，由板端 RcInput_Build 折算成 omega 后打进发往车的 RF 帧
> （与物理开关同一条代码路径，折算不重复做两遍）。板端解码值看 §5 的
> `o=` 字段（旧固件无此字段，重烧后可见）。

> 为什么是逻辑量而不是模拟电位器原始值：网页是发送端的一部分（输入适配归
> 发送端，2026-10-11 裁决），直接产出 rc_cmd.h v2 冻结帧的同名逻辑量，跳过
> 物理摇杆才需要的设备清噪死区/归一化（那是 PHYS 路径 `RcInput_NormalizeAxis`
> 的事）。手感死区/平方曲线在**车端** chassis Shape，两条路一致。

## 3. keys 方向刀位图（与 rc_input.h 宏组逐位一致）

每只自复位船型开关占相邻两位：`bit[2n]`=第 n 只 A 刀（正向/拨上）、
`bit[2n+1]`=B 刀（反向/拨下），松手回中=两位全 0：

| 位 | 开关 | 帧消费 | 位 | 开关 | 帧消费 |
|---|---|---|---|---|---|
| 0/1 | K_1 A/B | 大臂 joint[0] +/− | 6/7 | K_4 A/B | joint[3] +/− |
| 2/3 | K_2 A/B | 小臂 joint[1] +/− | 8/9 | K_5 A/B | 手腕 joint[4] +/− |
| 4/5 | K_3 A/B | 爪子 joint[2] +/− | 10/11 | K_6 A/B | **整车旋转 omega +/−**（2026-10-16 拍板，速率=板端 ROBOT_KEY_OMEGA_RATE） |

bit12（K_EB）/bit13（K_SW）不出现在本帧——急停走独立 estop 字节，物理
K_EB 是轻触键由板自己读。同开关 A/B 同 1 = 矛盾输入，板端 Build 失安全归零。

## 4. 板端行为契约（网页必须知道的）

- **看门狗**：板 500ms（`ROBOT_WEB_WATCHDOG_MS`）收不到合法帧 → 停发 RF，
  车端 400ms 看门狗接管：指令 300ms 渐停 + 断链声光。**网页切后台即显式停发
  心跳**（visibilitychange hidden：收尾发一帧当前态再静默，回前台补拍恢复）
  ——人不在页面前台不驾车。~~浏览器后台节流会自然断心跳~~（2026-10-17 勘误：
  开着 Web Serial 串口的页面 Chromium 不节流定时器，切后台 20Hz 照跑，
  赌节流链路断不掉，必须显式停）。
- **复连**：板恢复收帧即恢复发送，快照取最新帧；网页重连时必须先把 UI 复位到
  全零（摇杆回中、开关回中）再发帧。
- **急停闩锁**：网页侧点击闩锁、再点解除（不依赖按住）；物理 K_EB 按住置位，
  两条路径在帧字段上同构。
- 板上电即静默（等网页帧），`[RMT] init OK` 后 `w=d` 直到首帧到达。

## 5. 上行（板 → 网页）：`[RMT]` 文本行

WEB 模式统计行（1Hz）：

```
[RMT] tx=98 fail=0 seq=201 v=(311,-468) o=-500 k=0x0800 e=0 w=u ok=185 err=0 dr=12
```

| 字段 | 含义 |
|---|---|
| tx / fail | RF 发包成功/失败计数（车端视角的链路健康） |
| seq | RF 帧序号（u8 回绕，与 wseq 无关） |
| v=(x,y) | 板端归一化后的 vx/vy（±1000 逻辑量）——**对账利器** |
| o | 板端解码出的 omega（K_6 旋转，±ROBOT_KEY_OMEGA_RATE）——**按住 K_6 应看到 ±500** |
| k=0x… | 板端消抖后的方向刀位图（应与网页所发一致） |
| e | 急停位 |
| w | u=网页链路活 / d=看门狗超时停发中 |
| ok / err / dr | 串口侧累计：合法帧 / CRC 错帧 / 帧头外丢字节 |

判读：`err`、`dr` 齐涨 = 波特率不对或没在发本协议；只有 `dr` 涨 = 帧头错位；
`w=d` = 网页断流（看板日志同时打 `web lost` 行）；**按住 K_6 而 o 恒 0 =
板上跑的是旧固件（omega 解码前版本），重烧 `build/Debug/Remoter.elf`**。
其余 `[RMT]` 行（init/web up/lost）按纯文本进日志窗。

## 6. 摇杆↔指令方向约定（与车端/数字孪生习惯一致）

- 单位：vx/vy=逻辑量 ±1000（0=回中）；**vx=纵向（前后），vy=横移（左右）**。
- W（前）→ vx=+1000；S → vx=−1000；D（右移）→ vy=−1000；A（左移）→ vy=+1000。
- 摇杆**推上=vx+（前进）、推左=vy+**（2026-10-16 实车方向二次修正）。
- Q → K_6A=+omega（左转）；E → K_6B=−omega（右转）。omega 的实际转向由
  车端几何/SIGN 决定，M3 上车冒烟时架空核对。
- vx/vy/omega 正负在车上对应哪个真实方向归车端几何，发送端不管。
