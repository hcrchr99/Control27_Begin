## 一、F103RC 时代（S1~S7，2026-09 ~ 2026-10-03）

### 1. S3 编码器四路症状各异 → 共地（2026-09）

- **症状**：四路编码器现象各异——恒单方向 / 跳动 / 串扰（ENC2 恒 -20），换任何配置无效。
- **定位**：LA 抓信号正常 + 固件打 IO 电平串逐步排除 → 锁定参考地。
- **根因**：编码器与 MCU **未共地**，电平参考漂移。
- **修复**：共地。
- **教训**：①"计数规整但方向恒定不随换向翻转"= 两相非 90° 正交，不是软件问题；②四路现象一致优先怀疑共性信号源；③悬空 NOPULL 输入拾取串扰是正常现象；④`(int16_t)(now-last)` 回绕差分数学正确，别怀疑它。**器件一定要共地（README 第一戒律）。**

### 2. S2/W1 nRF24 链路三案（2026-09-30）

**案 2.1 命令字节被掩码**：`W_TX_PAYLOAD(0xA0)/R_RX_PAYLOAD(0x61)` 被 `reg & 0x1F` 拼装 → 0xA0&0x1F=0x00，"发载荷"静默变"写 CONFIG"，无线电永不发射而 SPI 读回全部正常。
**教训**：≤0x1F 才拼 W_REGISTER 前缀，数据类指令原样发；**判断 TX FIFO 状态不能只看一次静态读**（FIFO_STATUS 复位值 0x11 会假阳性）。

**案 2.2 码率编码错误**：RF_SETUP 的 [RF_DR_LOW,RF_DR_HIGH] 编码写反——"1Mbps"实际配成 250kbps。两端同错不影响互通，但**兼容片解释不一致 → 能量听得见（rpd=1）包解不出**。统一真 1Mbps 后立即打通。
**教训**：驱动必须逐位对照手册（Table 28），"两端一致"掩盖不了"两端同错"。

**案 2.3 MCU 复位 ≠ 模块复位**：复位期间模块 VCC 不断电，STATUS 残留 RX_DR；PreCheck 硬性要求 0x0E 导致"收包中按 Reset 必初始化失败"。
**教训**：对接"复位后行为异常"先分清 MCU 复位和外设复位的边界；判据放宽为总线存活（0x00/0xFF 判死），靠重配置恢复。

### 3. S5 TIM5 步距 20µs → 2µs（2026-09-30 / 10-02）

- **症状**：PM10S 死区 µs 级，20µs 量化导致大臂定位肉眼可见跳格。
- **修复**：PSC 1440→144、ARR 1000→9999（50Hz 保持，分辨率 1.8°→0.18°/步）。
- **教训**：**CubeMX 改时基必须同步 bsp_pin.h 常量（ARR/US_PER_STEP）**，否则 SetPulseUs 按 US_PER_STEP 换算出 10 倍偏差。

### 4. S6 ADC 双坑（F1 从机缺配，2026-10-06 两轮破案）

**坑① 从机 EXTTRIG 无人置位**：raw_v 恒 2000≈VDDA/2、PA5 接 GND/3.3V 均无反应。根因链（HAL 源码注释自相矛盾实锤）：F1 `HAL_ADC_Init` 有意不置 CR2.EXTTRIG（留给 Start_xxx），而 `HAL_ADCEx_MultiModeStart_DMA` 只给主机置位——从机永不触发。
**坑② 从机 CONT=DISABLE**：补 EXTTRIG 后 raw_v 恒轨。CubeMX 给从机生成 ContinuousConvMode=DISABLE（.ioc 缺项=默认 DISABLE），主机连续自触发不再产生新边沿、从机停转。
**修复**：坑② 由 .ioc 源头配置；坑① 运行期 `SET_BIT(EXTTRIG)`（HAL 行为缺口 CubeMX 填不了）。**F407VG 迁移后此两坑均不存在**（见二.4 勘误#2）。
**方法论**：用户板上判别（PA4 全链路通、PA5 纹丝不动 → 问题锁定从机转换链）→ HAL 源码逐行审计找注释与实现矛盾 → 逐轮单变量修复。

### 5. S6 链路标定与 VDDA 漂移（坑#13，2026-10-06）

- **症状**：V_K=0.9745 烧入后复测仍散且"误差越来越大"。
- **根因**：USB 供电不稳，VDDA 下漂（3.21V→3.11V）。**ADC 基准=VDDA，标定系数只在标定时的供电形态下有效。**
- **修复**：换电源模块供电，复标 V_K=0.993。
- **纪律**：供电形态变更（含最终上电池、换板）**必须复标**。F407VG 上板后 V_K/JOINT_I_K 同样待复标。

### 6. S6 测试台按键节拍（2026-10-06）

KEY1 消抖写在 500ms 打印门后，"连续 3 拍一致"实为 1.5s 长按。
**教训**：测试台 Poll 内的输入采样必须跟 10ms 调度节拍，打印门只管打印。

### 7. S7 OLED 首屏 NaN + 充电泵（2026-10-03）

- test_oled 初版漏调 `Power_Init`，V/I/P 全 NaN 显 -1。**教训：测试项引用跨模块数值源时先调该模块 Init。**
- SSD1306 充电泵 0x8D 0x14 漏发=全黑；拔插排线=模块掉电，须重发 init（Oled_Refresh 连败 5 次自动重发）。

### 8. S0 教训：CMSIS 实例宏 ≠ HAL 句柄

`UART4`/`TIM4`/`ADC1` 等实例宏是寄存器块指针，严禁强转当句柄；HAL 句柄一律用 `huart4`/`htimx`/`hadc1`（extern 自 CubeMX 头文件）。

## 二、F407VG 迁移时代（2026-10-05 起）

### 1. 时钟树：定时器时基三连错（2026-10-05）

- **症状**：升 168MHz 后电机 PWM=10kHz（应 20k）、SG90 组 25Hz（应 50）、PM10S 组 244Hz（应 250）。
- **根因**：CubeMX 里 APB1 分频=DIV4（APB1 定时器时钟 84MHz），而定时器数值按"APB1 定时器=168MHz"推算照抄。
- **修复**：TIM4 4200-1、TIM5 PSC 168-1、TIM9 PSC 336-1/ARR 2000-1（全部按各自 APB 定时器时钟重算）。
- **教训**：**定时器 PSC/ARR 必须按各自所在 APB 的定时器时钟核算；改时钟树先看分频再动定时器。** APB1 保持 DIV4 是有意为之（SPI2 5.25MHz，DIV2 会超 nRF24 10MHz 上限）。

### 2. CMake：CubeMX 生成物的三个坑（2026-10-05）

**坑 2.1 链接脚本路径**：CubeMX 工具链文件用 `CMAKE_SOURCE_DIR` 引 `.ld`——只在单独打开工程时正确；根门面 `add_subdirectory` 配置时指向仓库根 → 链接失败。**F103RC 初版同款坑**（git 2695bf3 实锤），2026-09-30 门面重构时手工修过被忘。
**自愈修复**：CubeMX 永不覆盖的 `Hardware/F407VG/CMakeLists.txt`（generated only once）里加 `string(REPLACE)` 钩子，无论工具链文件是坏是修一律按本文件位置解析——**重生成后无需任何手工补丁**（已模拟 regen 实证）。

**坑 2.2 换工具链的缓存残留**：CMake 按 binaryDir 缓存编译标志，换工具链不自动失效 → 残留 `-mcpu=cortex-m3`。删 `build/` 目录重配解决；F103RC 退出门面后单工具链不会再发。

**坑 2.3 相对 toolchain 路径**：`-DCMAKE_TOOLCHAIN_FILE` 传相对路径会在早期解析阶段落空（报 CXX compiler not set），必须绝对路径。

### 3. 日志口：UART4/PC10 悬案 → USART2（2026-10-05，未完全结案）

- **症状**：UART4 阻塞式发送分析仪与万用表均无输出；PC10 实测 1.12V。
- **分析**：推挽 AF 输出物理上不可能停 1.12V——那是高阻/浮空特征（万用表量浮空脚无意义）；PC11 的干净 3.3V=被 USB-TTL TX 驱动，接线正确。**最可能是探头插错排针**（新板排布≠F103RC）。
- **处置**：改在 CubeMX 启用 **USART2（TX=PD5/RX=PA3）**，阻塞式立刻通，bsp_log 全链换挂 huart2。UART4 在 CubeMX 保留备用。
- **结案条件**：核对 `GPIOC->MODER`(bits21:20=10)/`AFR[1]`(bits11:8=0x8)——若配置全对则 UART4 一直是好的，纯探头位置问题。

### 4. ADC 坑#5：F4 HAL 只使能多模式主机（2026-10-05）

- **症状**：Adc_Init 三步全 OK，但 raw 恒 0、ADC3 轮询全失败（后拆分为两案）。
- **定位**（J-Link 活体寄存器）：ADC2 `CR2.ADON=0 / SR=0`（从未上电）、CDR=0、ADC1 `SR=EOC|STRT|OVR`、s_pair_buf 全零、DMA SxCR/NDTR/CH 配置全对。
- **根因**：F1 的 `HAL_ADCEx_MultiModeStart_DMA` 会 `ADC_Enable(&tmphadcSlave)` 连从机上电；**F4 同名函数无从机处理**（源码对比实锤）——从机 ADON 无人置位 → 双同步对永不完成 → CDR 恒 0 → DMA 请求零 → 主机独跑自溢出 **OVR 置位**。RM0090 §13.8.1：**OVR=1 时 DMA 请求被硬件封锁**，且我们未开 ADC 中断无人清 → 死锁。
- **修复**：`Adc_Init` 里 MultiModeStart 之前 `__HAL_ADC_ENABLE(&hadc2)`（主机 Tstab 顺带覆盖从机稳定）。
- **教训**：HAL 在两代芯片间的同名 API 语义会变——**多模式启动这类"跨实例联动"必须看本代 HAL 源码**，F1 经验只能当线索不能当结论。

### 5. ADC 坑#6：MULTI≠0 屏蔽 ADC3 独立启动 → 双 rank 重架构（2026-10-05）

- **症状**：坑#5 修复后 V/I 活了，ADC3 仍全灭；插桩定位 `HAL_ADC_Start` 成功但 SR 恒 0（连 STRT 都不置）——转换从未开始。
- **活体实验**：J-Link 运行期清 CCR.MULTI → ADC3 **立即复活**。
- **根因**：F4 的多模式开关在三 ADC **共享的公共 CCR** 上（F1 的 DUALMOD 只在 ADC1.CR2、管不到 ADC3），MULTI≠0 期间 ADC3 的软件启动被集群接管屏蔽。"双同步 + ADC3 独立轮询"的 F1 架构在 F4 上不成立。
- **修复**：ADC3 退役，J0/J1 并入双同步序列 **rank2**（ADC1: IN4+IN12，ADC2: IN5+IN13——等长序列正是 RM0090 §13.9 双同步的前提）。一条 DMA 全包四通道，字流偶=V/I 对、奇=J 对；J 采样从"按需轮询（2ms 超时路径）"升级为"连续采样（无阻塞）"，对 W2.4 堵转判据更友好。
- **教训**：外设架构差异不是 bug，硬搬 F1 拓扑才是。**公共寄存器上的模式位影响面 = 整个外设集群**，别按"单例寄存器"直觉推。

### 6. J-Link 闭环调试工具链（tools/，2026-10-05 建立）

- **为什么不是 OpenOCD**：本机 J-Link 被 Segger 官方驱动独占（Ozone 在用），sysprogs OpenOCD 走 libusb 抢不到设备；换 WinUSB 驱动会废掉 Ozone。方案=**JLink.exe Commander 脚本**（与 Ozone 共存）。
- **三件套**：`tools/flash.sh`（loadfile+reset+go）、`tools/serial_snap.py`（pyserial 自动嗅探日志口+时间戳抓取，COM14/CH343）、`tools/adcregs.sh`（mem32 活体读寄存器）。
- **操作纪律**（血泪三连）：①mem32 输出行首是地址，grep 过滤别漏前缀不同的行；②DMA2_Stream0 寄存器偏移 CR=0x10/NDTR=0x14/PAR=0x18/M0AR=0x1C（NDTR 读成 PAR 会看到"地址值"假象）；③脚本结尾必须 `g` 恢复运行，否则核被 halt、后续串口全哑；④ADC 公共块基址 0x40012300，CCR=+0x04（不是 +0x304）。

## 三、F407VE 时代（2026-10-07 换板起）

### 1. 坑#15：DWT 带 CoreSight LAR 锁（2026-10-07 破案）

- **症状指纹**：DWT_CTRL/CYCCNT/LSR 三个寄存器读出**同一个值 0x40000001**（总线常数），使能序列全对也不计数；CPUID 等非 DWT 地址读数正常。
- **根因**：F407 修订 5/6（REV_ID=0x101F）换了带锁的 CoreSight 宏单元，LAR 默认上锁=软件视角"DWT 不存在"。DEV_ID 遮罩误读曾把正品判成兼容片（被用户拿手册纠正——验芯片按位段遮罩读，这是新板 bring-up 第一步）。
- **修复**：写 0xC5ACCE55 到 `DWT_LAR(0xE0001FB0)` 解锁再走使能链；`Bsp_DwtReArm()` 任务级幂等补枪——**J-Link 断开会把调试域打回**（烧完不按复位直接跑会再冻结），纯上电/NRST 无此问题。
- **教训**：①调试器挂载污染被测对象（连接自动解锁、断开清域）——"调试器在场活、离场死"=观测陷阱，终审走无调试器路径；②J-Link mem32 与内核软件视角可能不一致，寄存器疑问以固件自证为准。

### 2. 测速窗 ×2（2026-10-09）

- **症状**：固定系数折算的转速整体 ×2（表显 500 vs 铭牌 320）。
- **根因**：折算按"标称 20ms"窗长，实际窗 40ms——任务节拍≠1kHz（Poll 10 拍+调度周期）。
- **修复**：折算改用 Bsp_GetUs 实测窗长；CALC_MS 语义改"窗长下限拍数"。
- **教训**：凡"按标称时间折算"的系数必须用实测时间；用户以示波器 A 相 625Hz 对表定案。

### 3. CYCCNT 回绕（坑#15 家族第二案，2026-10-09）

- **症状**：整定台周期性转速深谷，间隔精确 25.6s。
- **根因**：CYCCNT 32bit@168MHz 每 **25.57s** 回绕（旧注释"71.6min"漏算本体回绕）；跨回绕差分爆 2³²µs 假窗长→rpm 假归零→PID 拉满 duty→锯齿恢复。
- **修复**：无符号差分+扩展快照，且累计器必须 **uint64_t**（首版 u32 自身同周期溢出，双口对审实锤后才补）；Bsp_DwtReArm 清 CYCCNT 须同步清扩展快照。
- **教训**：修回绕时新增的中间量自己也是回绕体——计数器/累加器/返回值每层单独验容量；修复后跑 3+ 个回绕周期复验；黑匣子（异常自动留档）一次抓到指纹。

### 4. bsp_vofa 命令全哑（2026-10-09）

- **症状**：UART4 硬件收到命令无任何反应，JustFloat 发送正常。
- **根因**：HAL RX 回调全仓唯一定义点在 bsp_log.c，UART4 分支误把 **USART2 的 log_rx_byte** 传给 vofa 行装配器——字节源顶包。
- **修复**：`Bsp_Vofa_OnRxIrq` 从自持 `s_rx_byte` 取字节。
- **教训**：共享 HAL 回调的多外设分支，各自只准消费自己的缓冲；"发送通、接收哑"先查回调分发的字节源。

### 5. vofa ReadLine 竞态（2026-10-11 修，随 W2.4 快照入库）

- **症状**：偶发丢命令首字节（低概率）。
- **根因**：`Bsp_Vofa_ReadLine` 先清 `s_line_ready` 后清 `s_line_len`，两句之间 ISR 携新行字节按旧 len 续写，首字节落进上一行残尾整行错位。
- **修复**：拷贝-清零整段 `__disable_irq` 原子化（拷贝 ≤24B 约 1µs@168MHz，UART 接收中断推迟无感；契约=仅任务侧调用）。
- **教训**：与 ISR 共享的多字段状态，**"清零顺序"也是竞态窗口**；原子段要覆盖整个"拷贝+清零"动作。

### 6. 主控烧毁案（2026-10-10 确诊，换片 10-13 完成）

- **症状链**：ST-Link "Unable to get core ID"（hotplug/各速率全败）→ USART2 无日志 → BOOT0=1 出厂 bootloader 仍连不上（排除一切软件）→ 芯片微温 → 上电快速发热 → VDD-GND 万用表仅 20Ω=电源-地低阻短路实锤。
- **肇因：未定案**。曾怀疑接无源蜂鸣器（PA7 直驱）等接线操作时的电气应力（带电插拔/短路/感性反冲），但**用户实证接蜂鸣器之前板就已异常**——该嫌疑被时间线排除；真肇因待查，芯片已毁大概率无法定案（不排除更早的供电/接线应力或个体缺陷，不作断言）。
- **教训**：①电压读数稳+芯片微温**都不能证明健康**——内部损伤渐进恶化，"现象一直在变"是同一伤口溃烂的不同阶段；②BOOT0 试金石一次排除所有软件因素；③换片流程：拆片复量 VDD-GND（恢复高阻=板干净）→新片不带外设上电摸温→烧已知好固件看心跳→逐个回插外设。
- **结案**：2026-10-13 新板点检通过且全日板验（命令链/舵机/声光）无异常，持续性环境根因的可能性降低；断电插拔、先共地等接线纪律作为通用守则继续执行（承 S3 共地案，不系于已排除的蜂鸣器嫌疑）。

### 7. UART4/PC10 悬案结案（2026-10-13）

F407VE 上 UART4@921600 双向常年工作（W2.3 整定、W2.4 三交互台全走此口）——VG 时代的"PC10 实测 1.12V"按**探头插错排针**结案，"配置存疑"不成立。教训沉淀：推挽 AF 输出物理上不可能停高阻电平，量到浮空特征先怀疑探头位置，别急着怀疑代码。
