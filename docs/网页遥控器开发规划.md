## 一、定位与核心原则

Remoter 输入硬件（摇杆电位器、船型开关、急停按钮）未到位，实车调试缺发送端。网页遥控器
= 物理输入的替身：网页模拟实际遥控器的全部控件（1 摇杆 + 6 只自复位船型开关 + 急停），
经 USB-TTL 串口喂给 Remoter 核心板，走既有发送链经 nRF24 打到车端。真件焊上后固件切回
物理采集，网页台退役为备份遥控。

**核心原则：网页只替代"物理输入采集"这一段。** 网页发的是摇杆原始值（0..4095，模拟
电位器）与方向刀位图——死区、归一化、建帧、"整帧清零再填"纪律全部继续走固件既有
单一入口（RcInput_Build），映射逻辑零分叉。车端 15B 冻结帧、400ms 看门狗、失联渐停、
链路声光全部原样复用。

## 二、架构（已实现）

```
┌─ 网页遥控台（PcTwin/web_pilot/，Chrome/Edge + Web Serial API）────────────┐
│ 摇杆(拖拽/WASD)  6×三态船型开关(指针/键盘)  急停(点击闩锁/空格)  [RMT]遥测面板 │
└────────┬──────────────────────────────────────────▲─────────────────────┘
    10B 帧 @20Hz心跳+变化即发(≥15ms)          [RMT] 文本日志行(1Hz 统计+事件)
    (USB-TTL, TX/RX 交叉, 共地, 3.3V)                    │
┌────────▼──────────────────────────────────────────┴─────────────────────┐
│ Remoter 板（F103C8T6，ROBOT_RMT_INPUT_WEB=1）                             │
│ USART1@115200 Log_Poll 拉字节 → web_input 解析(0x5A+CRC8+滑窗重同步)       │
│   → 看门狗 500ms 判新鲜 → RcInput_Build 建帧 → 100Hz nRF24 PTX 发包        │
│ 断流 → 停发 RF（车端看门狗接管：渐停+断链声光）；事件行 web up/lost        │
└───────────────────────────────────────────────────────────────────────────┘
```

20Hz 网页帧与 100Hz RF 帧解耦：MCU 每拍取最新快照建帧（与物理开关按住不动同语义）；
RF seq 只在实发帧递增（PTX 纪律），网页 wseq 只做串口段诊断。

## 四、串口线协议 v2（已实现，权威定义=PcTwin/web_pilot/PROTOCOL.md）

**下行（网页→板）10B 定长小端**：

```
[0]=0x5A | [1]=wseq u8 | [2..3]=vx i16 ±1000 | [4..5]=vy i16 ±1000
| [6..7]=keys u16 方向刀位图 | [8]=estop u8 | [9]=CRC8([1..8])
CRC8: poly 0x07、初值 0x00、不反射、无异或输出（"123456789"→0xF4）
```

- vx/vy=**轴逻辑量**（rc_cmd.h v2 冻结帧同名同义，网页直传+发送端钳位；
  PHYS 路径的原始 ADC 经 RcInput_NormalizeAxis 在采集侧产出同一形态）。
- 节奏：20Hz 心跳 + 变化即发（≥15ms）；无应用层重传（错帧丢弃等下拍）。
- 板端解析：任务上下文 Log_Poll 拉字节 → 扫帧头 → 攒 10B → CRC 判定 →
  逐字段小端解出 RcInput_Raw_t 快照+时间戳；错帧滑窗重同步（缓冲内找下一个
  0x5A，坏帧夹好帧可完整恢复——test_web_input 已固化该行为）。
- estop 字节板端按非零即急停消费；网页打包器规范化为 0/1。
- **上行=既有 [RMT] 文本日志通道一字不改**。WEB 模式统计行扩至：
  `[RMT] tx= fail= seq= v=(x,y) o= k=0x… e= w=u|d ok= err= dr=`
  （o=板端解码出的 omega，按住 K_6 应见 ±ROBOT_KEY_OMEGA_RATE；w=网页链路态；
  ok/err/dr=串口侧合法帧/CRC 错帧/帧外丢字节，err+dr 齐涨=波特率不对，
  独 dr 涨=帧头错位）。web up/lost 事件各打一行。

## 八、坑与纪律（预登记/已应验）

1. **RcInput_Raw_t 两端同步**：固件改字段必须同步网页打包器与 PROTOCOL.md
   （串口帧无编译期护栏）；改 web_input.h 帧注释同理。
2. **[RMT] 行格式**是网页解析契约：改统计行格式须同步 main.js 的 RMT_RE。
3. **Chrome 后台节流**：后台标签 20Hz 心跳必掉 → 车渐停——特性非故障，
   页面横幅已注明；回前台自动补帧恢复。
4. **setPointerCapture 假 pointerId**：合成事件/边缘时序会抛异常拦住后续
   处理，一律 try/catch（数字孪生 joy 同款教训）。
5. **ES module × file:// = 整页静默死亡**：`<script type="module">` 走 CORS
   加载，file:// 页面直接被拦——症状恰是"所有按钮点击无反应"而非报错弹窗，
   极具迷惑性。本页已改经典 `<script defer>`（main.js 保持零 import/export
   是纪律：谁引入模块语法谁负责换 http.server）；页面 load 时自检
   WebPilotDebug 未定义即弹横幅自诊断。
6. USB-TTL 接线：TX/RX 交叉、共地、3.3V（板 PA9=TX→线 RX，板 PA10=RX→线 TX）；
   日志输出口=网页输入口，同口双向方向不对称无冲突。
7. WEB 模式上电即静默（等网页帧），init OK 后 w=d 直到首帧——这是预期不是故障。
8. **"某指令不起作用"先查板端固件版本**：网页帧监视只证明网页发了（如
   keys=0x0800），不证明板端解码——旧固件（omega 解码前）会静默吃掉 K_6。
   判读靠 [RMT] 行 o= 字段：按住 K_6 而 o 恒 0=重烧 build/Debug/Remoter.elf。
9. 拖拽类控件三件套防"卡住"：user-select:none + pointerdown preventDefault
   + window 层兜底 release（拖选/原生拖拽会抢走指针流，🚫 光标是拖选指纹）。
