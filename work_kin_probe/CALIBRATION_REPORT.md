# 机械臂运动学标定与修复记录（2026-10-12）

## 问题现象

仿真/实机界面里，机械臂在某些姿态下"按了没反应"——明明视觉上还有行程，软件却一步都不动。

## 根因（两条）

### 根因 1：FK 与 IK 的自洽性被破坏（9.14 mm）

`robot_config.h` 的注释写着：

```
TCP0 − 腕俯仰轴(242.077, 157.838) = R4 = (70.673, −47.818)
```

`kinematics.c` 的 `Kin_IkNormal()` / `r4_vec()` 用的正是这个 R4（|R4| = 85.329 mm）。
但 `Kin_Fk()` 走的是另一条链 `WRIST(23.723, 21.742) + TOOL(77.723, −53.638)`，它推出来的
腕俯仰轴→爪心是 **(319.800, 104.198)**，与 `TCP_X/Z_MM = (312.750, 110.020)` 差 **9.143 mm**。

后果：逆解算出的关节角喂回正解，爪心落点与期望差 9 mm；且逆解的目标点被
错误地放到可达边界外，全线判不可达。

### 根因 2：`SING_MARGIN = 0.02` 过大，把建模位误判为奇异（主因）

```
建模位（三关节全 90°）：
  肩 → 腕俯仰轴 = 223.1152 mm
  大臂 + 小臂可伸最长 = 223.1197 mm
  余量 = +0.0044 mm          ← 只有 4 微米
  cos(Δ) = 0.999919  →  1 − |cos| = 0.000081
  拒判阈值 SING_MARGIN = 0.0200
  ⇒ 0.000081 < 0.0200，每一个逆解都返回 false
```

`solve2r()` 里的 `1−|cos| > margin` 相当于要求**两连杆夹角 > 11.5°**。
而建模位（也就是 `links.json` 全零角、实机开机位）本身就是"几乎完全伸直"的位形，
所以**从建模位出发的任何直线运动都被整条拒绝**，一步都不动。

用户截图那个姿态（大臂 104° / 小臂 101° / 手腕 55°）更极端：

```
腕俯仰轴到肩 = 226.43 mm   >   可伸最长 223.12 mm
⇒ 超出 3.31 mm，在模型里根本不可达
```

## 修改

### `Bsp/robot_config.h`

```diff
-#define ROBOT_ARM_TOOL_X_MM         77.723f
-#define ROBOT_ARM_TOOL_Z_MM         (-53.638f)
+/* 2026-10-12 重新标定：原值使 Kin_Fk(90,90,90) 得 (319.800, 104.198)，
+ * 与 TCP_X/Z_MM 差 9.143mm。数值标定解得 |G|=85.3294mm、安装角 −34.0815° */
+#define ROBOT_ARM_TOOL_X_MM         70.6734f
+#define ROBOT_ARM_TOOL_Z_MM         (-47.8161f)

-#define ROBOT_ARM_SING_MARGIN       0.02f
+#define ROBOT_ARM_SING_MARGIN       0.0015f
```

标定方法：极坐标网格 + 精化搜索（`work_kin_probe/calib_final.c`），
目标函数 = `|Kin_Fk(90,90,90) − TCP0|`。

原文件备份在 `Bsp/robot_config.h.bak_2026-10-12`。

## 遗留事项

1. **起点（i=0）逆解仍返回 false** —— 这是设计允许的：`Kin_LineStart` 在 `i==0`
   失败时 `continue`（起点是当前姿态本身，不必可达）。若要消除，可把
   `SING_MARGIN` 再降到 < 8.1e−5，但不建议（会失去真奇异保护）。

2. **`el_in_limits()` 的映射仍是舵机满量程**：`ROBOT_SERVO_LIMIT_MIN/MAX_DEG_LIST`
   目前是 `{0…180}`，等价于仰角 ±90°。等实机舵机收紧行程后改这两个列表，
   `kinematics.c` 会自动跟进。屏幕上的关节滑动条范围应与之保持一致，
   否则会出现"UI 说还能动、代码说越限"的错觉。

3. **`Kin_Fk` 的 0.0004 mm 残差**来自 `f` 后缀单精度与标定步长，实际可忽略。
